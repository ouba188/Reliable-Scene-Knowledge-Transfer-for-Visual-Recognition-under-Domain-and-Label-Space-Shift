# (a) 域相关可分性：源港留一线性探针 v1

**问题**：冻结特征 `z`（512 维）在跨港时丢掉了多少可分性？简单的二阶对齐（CORAL）能不能补回来？
**协议**：只用源端实例、源端真标签；目标端完全不参与。

## 一、做法

对每折的每个源港 P（≥150 标签）：
- `cross`：用**其它源港**训练逻辑回归探针 → 在 P 上评估
- `in`：在 P 内部 5 折交叉验证（域内上界）
- `coral`：把 P 的 `z` 用 CORAL（白化+重着色，仅用 z、不用标签）对齐到其它源港 → 再用 cross 探针评估
- `gap = in − cross`（域间隙）；`恢复 = coral − cross`

`z` 先 PCA 到 64 维（512 维逻辑回归慢约 10×，跨港 vs 域内的对比量在投影后仍保持）。

## 二、结果

| 折 | 源港数 | 平均域间隙 `in−cross` | CORAL 平均恢复 |
|---|---:|---:|---:|
| Rotterdam | 4 | **+0.484** | −0.136 |
| Shanghai | 2 | **+0.575** | +0.070 |
| Port Klang | 4 | **+0.409** | −0.280 |
| Fujairah | 4 | **+0.543** | −0.106 |
| Jebel Ali | 2 | **+0.388** | −0.257 |
| Port Said | 4 | **+0.518** | −0.135 |

个例（典型数量级）：Fujairah→Shanghai cross .365 / in .740；Port Said→Qingdao cross .294 / in .951；
Jebel Ali→Qingdao cross .574 / in .980。

## 三、两条读数

1. **域间隙极大且处处存在（+.39 ~ +.58）**：同一冻结表示在其它源港学到的线性判据，换到目标源港就掉
   40–60 个点；而域内可达 .70–.98。→ **表示是强港口特异的**，与 (a) 诊断中「同类跨港召回差 2 倍」相互印证。
2. **CORAL 二阶对齐没有帮助，6 折中 5 折反而更差**（−.11 ~ −.28）。→ 域间隙**不是均值/协方差的二阶偏移**，
   靠白化+重着色这类朴素适配补不回来。

## 四、口径与限制（必须一并写进论文）

- 这里测的是**冻结 `z` 上的线性探针**，不是头/模型的泛化（头在目标端仍可能有更好的表现）；
  它回答的是「表示的可分性在跨港时损失多少」，不是「模型最终精度」。
- PCA-64 是有意简化（`ponytail` 注释在脚本里），只影响探针效率，不改变跨港 vs 域内的对比方向。
- 域内 `.95+` 属于「2k 样本 + 64 维 + 同港同分布」的理想化上界，**不得当作可部署精度**。

## 五、对下一步的含义

域间隙（+.39~+.58）**比决策粒度缺口（+.03~+.08）大一个量级**。所以：
- 优先做**表示/适配层**（对应 (a) 的真实抓手），而不是继续在策略/阈值/子集上找涨分；
- 任何适配方法都应在**源港留一**协议上验证能否缩小 `gap`（本文件即该协议的基线：cross 与 coral 两列）。
